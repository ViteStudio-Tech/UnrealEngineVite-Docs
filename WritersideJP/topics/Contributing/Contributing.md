# コントリビュート

<tldr>
<p>
Vite には標準の Unreal より厳しいルールがあります。再帰の禁止、新しい仮想関数の禁止、新しいブループリントへの公開の禁止、厳格な Clang への準拠、そして完全な ABI の安定性です。プルリクエストを出す前ではなく、コードを書く前にガイドラインを読んでください。
</p>
</tldr>

Vite は、UE 4.27 を速く安定させられるからこそ存在します。そのどちらかを損なうコントリビュートは、存在意義を失わせます。以下のルールはゲームエンジンのフォークとしては異例なほど厳しいものですが、それは意図的なものです。

## 始める前に

<procedure title="コントリビュートの流れ" id="contribution-workflow">
    <step>
        <a href="Coding-Guidelines.md">コーディングガイドライン</a> を読みます。よくある C++ のパターンのいくつかは全面的に禁止されており、コードを書いた後に気づくと高くつきます。
    </step>
    <step>
        その変更がすでにカバーされていないかを確認します。<a href="Compile-Time-Switches.md">コンパイル時スイッチ</a>
        と <a href="Engine-Defaults.md">エンジンの既定値の変更</a> のページに、既存の作業の多くが記載されています。
    </step>
    <step>
        ブランチで作業します。作業途中のものは、残っている作業のメモを添えて別のブランチにプッシュし、他のフォークの作業者にも知らせます。
    </step>
    <step>
        確認します。MSVC でクリーンにコンパイルでき、Clang に準拠し、起動時、終了時、Tech Showcase のプロジェクトでクラッシュせず、ログを大量に出さず、ABI を変更していないこと。
    </step>
    <step>
        プルリクエストを出す前に <a href="Coding-Guidelines.md">レビューのチェックリスト</a> をすべて確認します。
    </step>
</procedure>

## プルリクエストの却下の大半を占める 3 つのルール

<deflist>
<def title="ABI の安定性">
レイトレーシングのペイロードのビットフィールド、シェーダーから見える列挙型やフラグ、RHI や RenderCore が使うパックされたビットマスク、リフレクションシステムのビットマスクの定義、CPU と GPU で共有する構造体のレイアウトを変更しないでください。これらを壊すと、PSO のキャッシュ、レイトレーシングの安定性、シリアライズ、ベンダーをまたいだ GPU の挙動が壊れます。ABI の違反は、変更の他の部分がどれほど優れていても即座に却下されます。
</def>
<def title="性能の基準">
変更は ARM クラスの約 1 GHz の CPU を基準に評価されます。デスクトップで計測して速かったというだけでは基準を満たしません。
<a href="Performance-Targets.md">パフォーマンス目標</a> を参照してください。
</def>
<def title="著作権の明確さ">
コントリビュートは、独自の作業か、寛容なライセンス（MIT、Apache 2.0、BSD、Zlib）のものでなければなりません。UE5 から
4.27 のフォークにコピーしたコードは Epic のライセンスの下にあり、寛容なライセンスとは別の問題です。
<a href="Backporting.md">バックポート</a> と <a href="License-And-Copyright.md">ライセンスと著作権</a> を参照してください。
</def>
</deflist>

## 良いコントリビュートとは

Vite によく合うコントリビュートには共通の形があります。

- **計測されている。** 代表的なコンテンツでの変更前と変更後のプロファイリングのキャプチャは、議論に勝ります。[Compiler Explorer](Compiler-Explorer.md) はアセンブリと Clang への準拠を確認するためのもので、フレームタイムのためのものではありません。
- **ガードされている。** 出荷に必要のないものは、[コンパイル時スイッチ](Compile-Time-Switches.md) かコンソール変数の背後に置き、コストがかかるなら既定でオフにします。
- **範囲が狭い。** 1 つのサブシステムに触れる変更はレビューできます。レンダラー、物理の層、ビルドシステムに同時に触れる変更はレビューできません。
- **ドキュメント化されている。** 新しいコンソール変数、スイッチ、既定値には、ドキュメントのページか、既存のページのセクションが必要です。
