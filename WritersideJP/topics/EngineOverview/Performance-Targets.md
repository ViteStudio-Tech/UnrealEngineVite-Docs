# パフォーマンス目標

<tldr>
<p>
PS5 クラスを基準とした 4 つの構成があり、いずれもレイトレーシングを含みます。スタイライズドの <b>4K120</b>、パフォーマンスの <b>4K60</b>、フィデリティの <b>4K30</b>、そしてレイトレーシングエフェクト一式を使う
<b>1440p30</b> です。数値はすべてネイティブ解像度です。
</p>
</tldr>

Vite のパフォーマンス目標は、願望を込めた宣伝用の数字ではありません。エンジンのチューニングの基準であり、デモプロジェクトが達成するよう作られている構成です。どの目標もレイトレーシングを含み、アップスケールした内部解像度ではなくネイティブ解像度で示しています。

[![Vite のレイトレーシング GI とレイトレーシング反射](https://img.youtube.com/vi/2vfG3W-Gy5E/maxresdefault.jpg)](https://youtu.be/2vfG3W-Gy5E)

*Vite で動作するレイトレーシング GI とレイトレーシング反射。クリックすると YouTube で再生します。*

## 4 つの目標

| 目標 | 解像度とフレームレート | 機能構成 | 想定する用途 | 実演 |
|---|---|---|---|---|
| **スタイライズド** | 4K、120 FPS | RT DDGI | 対戦型マルチプレイヤータイトル | スタイライズドデモ |
| **パフォーマンス（ハイエンド）** | 4K、60 FPS | DDGI + RT 反射 + テッセレーション | 品質を重視しつつ 60 FPS が必要なタイトル | Unreal Tournament Vite シーン |
| **フィデリティ（ハイエンド）** | 4K、30 FPS | 上記をジオメトリ密度に合わせて拡張 | 大規模オープンワールド | デモ制作中 |
| **フィデリティ（フル RT）** | 1440p、30 FPS | DDGI + RT 反射 + RTAO + RT シャドウ | 最高の画質 | NVIDIA デモ |

4 つすべての基準ハードウェアは PlayStation 5 クラスです。デスクトップでは、CPU の FPU 依存の処理（PhysX 3.4、アニメーションの SIMD）に **AMD 4700S**（Series X より削減された Zen 2 で、FMA パイプは 1 本）を、GPU にはおおよそ
RDNA2 の RX 6700 / RTX 2080 を使います。4700S の GPU は無効化されています。6700 は RDNA2 のコンパイラ挙動が十分に近いものの、PS5 の RDNA2 そのものではありません。[PS5 CPU の FPU](PS5-CPU-FPU.md) を参照してください。

コードベースには、リファレンス画像のためのパストレーサーも含まれていますが、既定ではコンパイル対象外です。[パストレーシング](Path-Tracing.md) を参照してください。リアルタイムのパストレーサーは Vite ReSTIR の一部として開発中です。

## 比較の前提

Epic の UE 5.7 と 5.8 は、Lumen、Nanite、VSM、TSR、Chaos を用いて、PS5 上で 720p〜1080p の動的内部解像度により約 60 FPS を目標としています。Vite の主要な主張は、その想定機能構成に対して実ゲームのフレームレートで最大 2.5 倍の基本性能向上です。

最も分かりやすい実例は、レイトレーシング GI、レイトレーシング反射、テッセレーションを使った Vite のシーンが、レイトレーシングも Lumen も Nanite もテッセレーションも使わない UE 5.7 の *同一シーン* を上回ることです。これは
RTX 4080 Super での 4K ネイティブ、RDNA2 の RX 6700 での 4K ネイティブ、そして Steam Deck のハードウェアでのネイティブ解像度で成り立ちます。

## 測定された基準値

以下はベンチマークシーンでの具体的な測定値で、上記の目標の裏付けとして掲載しています。いずれも同一シーンでの同条件比較です。

| 測定項目 | Vite | UE5 | 比率 |
|---|---|---|---|
| DDGI テストシーン、RTX 4080S、1440p ネイティブ | 811 FPS（RTXGI） | 324 FPS（Lumen 5.7） | 約 2.5 倍 |
| DDGI テストシーン、RX 6600、1080p ネイティブ | 245 FPS（RTXGI） | &mdash; | &mdash; |
| 物理のストレスシーン、3,000 キューブ | 157 FPS（PhysX） | 33.3 FPS（Chaos 5.7.3） | 約 4.7 倍 |
| 物理ソルバー、10,005 ボディ、6 スレッド | 11.76 ms（Vite PhysX） | 791.97 ms（Chaos） | 約 67 倍 |
| 物理、ネイティブ PhysX アクターパス、1,425 キューブ | 374 FPS | &mdash; | 同条件の比較ではない |
| キャラクタームーブメントとコリジョン | 4.27 を基準 | 5.6 | 4.27 のほうが 2.2〜2.8 倍高速 |
| 一般的なマルチプレイヤーマップのメモリ | 5.7 より約 1 GB 少ない | &mdash; | &mdash; |

DDGI の比較はレンダリング面の主張を、物理の比較は CPU 面の主張を最もよく表しています。ベンチマークシーン自体は
[プロジェクトとデモ](ProjectsAndDemos.md) からダウンロードできます。

## ネイティブ解像度を制約とする理由

時間的再構成、デノイズ、確率的サンプリングは、ノイズ、ゴースト、時間的な不安定さ、ブラーをもたらします。720p〜1080p の動的内部解像度から 4K に再構成した 60 FPS と、ネイティブ 4K の 60 FPS は、フレームレートの数字が同じでも別の製品です。

Vite の立場は、画像の鮮明さと操作の応答性こそが最初に劣化し、最も取り戻しにくいものだというものです。したがって、フレームタイムの予算はネイティブ解像度の維持と、原理的にノイズが出ないライティング手法に使うべきです。DDGI がデノイザーなしで安定した結果を出せるのは、プローブボリュームのイラディアンスを球面調和関数で保存・フィルタリングしているからです。

アップスケーラーは全面的にサポートしています。DLSS 4.5、FSR 4（FSR 3.1 へのフォールバック付き）、XeSS 3、NIS がすべてエンジンに同梱されています。これらは基準ハードウェアで目標を達成する手段ではなく、非力なハードウェアで目標を上回るための手段と位置付けています。[アップスケーラー](Upscalers.md) を参照してください。

## 目標に合わせて設計する

目標はアートの予算全体を決めるため、コンテンツを作る前に選んでください。

<procedure title="パフォーマンス目標を選び、守る" id="choose-target">
    <step>
        上の表からジャンルに合う行を選びます。対戦型マルチプレイヤーならほぼ間違いなくスタイライズドの 4K120、物語重視のシングルプレイヤータイトルなら通常はフィデリティを選べます。
    </step>
    <step>
        対応する機能構成だけを設定し、それ以上は加えません。DDGI は既定で有効で、個別のレイトレーシングエフェクトはオプトインなので、多くの目標では自分の行にあるエフェクトだけを有効にすることになります。
        <a href="Ray-Tracing.md">レイトレーシング</a> を参照してください。
    </step>
    <step>
        GI、反射、シャドウ、ジオメトリ、ポストプロセスなど、システムごとのフレームタイム予算を定め、最初のプレイアブルなシーンから <code>stat gpu</code> で測定します。
    </step>
    <step>
        対象ハードウェアのうち最も非力なもので、最後にまとめてではなく定期的にテストします。基準ハードウェアの一覧は
        <a href="System-Requirements.md">動作環境</a> を参照してください。
    </step>
    <step>
        最も非力なマシンを基準に設計してスケールアップするのではなく、<a href="Engine-Defaults.md">スケーラビリティ</a>
        の設定でスケールダウンします。
    </step>
</procedure>
