# PhysX テスト

<tldr>
<p>
4.27 向けの PhysX のテストレベル 5 つです。鉄球、ドミノ、かき混ぜる箱の中の球、積み上げるタワー、落下するキューブを収録しています。エンジンの変更後にビルドの物理が正しく動くかの確認と、ビルド間のコストの比較に使います。
</p>
</tldr>

## ダウンロード

[PhysicsTest のリポジトリ](https://github.com/tanger1n/PhysicsTest)

## 対象

各レベルには専用のゲームモードがあり、ブループリントのオーバーヘッドで計測が歪まないよう C++ からシーンを生成します。数、質量、サイズはプロパティとして公開されています。画面上にはオブジェクトの数と経過時間が表示されます。

| レベル | シナリオ | 負荷をかける対象 |
|---|---|---|
| `L_WreckingBall` | 重い球がレンガの壁に衝突する、または壁が重力で崩れる | 力積の伝達、大規模な同時崩壊 |
| `L_Domino` | 曲線状に並べたドミノの連鎖 | 接触の連続的な伝播とタイミング |
| `L_FluidParticle` | 容器に入れた 500 個の小さな球をかき混ぜる | 多数の同時接触によるブロードフェーズの負荷 |
| `L_TowerStacking` | タワーが崩れるまで上からキューブを落とす。最大 1000 個以上のボディ | 積み重ねの安定性、ボディ数 |
| `L_CubeFalls` | 基本的なキューブの生成 | 基準 |

物理に関わる何かを変更して、壊していないかを知りたいときに実行してください。大きなレベルは、変更前後のコストを手早く比較するのにも使えます。

## Vite との関わり

Vite は Chaos に移行せず PhysX を維持しており、その選択は、エンジンの変更を経ても PhysX の層が正しく保たれて初めて正当化できます。次のものに触れる変更は:

- 物理シーンやサブステップ、特に [`VITE_PHYSX_FIXED_TIMESTEP`](Fixed-Timestep.md) を有効にした場合
- ボディのインスタンスのトランスフォームや補間
- キャラクタームーブメントコンポーネントが多用する、コリジョンのクエリの経路
- Apex Destruction や Cloth の統合

完了とみなす前に、ここで確認すべきです。確認の要件は [コーディングガイドライン](Coding-Guidelines.md) を参照してください。

## 固定タイムステップのテスト

[固定タイムステップの物理](Fixed-Timestep.md) を評価するなら、このプロジェクトは違いを観察するのに適した場所です。Domino か Wrecking Ball を、フレームレートを制限せずに実行し、次に `t.MaxFPS` をさまざまな値にして実行します。既定の可変タイムステップでは結果がフレームレートによって変わり、固定タイムステップでは変わらないはずです。Tower Stacking でキューブのサイズをランダムにしている場合は、それだけで結果が変わるため、この比較には使わないでください。

固定タイムステップはコンパイル時の機能で、サブステップを有効にする必要もあります。ビルドに `VITE_PHYSX_FIXED_TIMESTEP=1` がなければ、`p.VitePhysXFixedTimestep.*` の変数は存在しません。
