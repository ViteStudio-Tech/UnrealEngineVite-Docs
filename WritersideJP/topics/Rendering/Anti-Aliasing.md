# アンチエイリアシング

<tldr>
<p>
Vite は、None、FXAA、TemporalAA、MSAA に加えて、4 つ目のアンチエイリアシング手法として <b>SMAA</b> を追加しています。SMAA は、特に対戦タイトルで最高の生の画質を得るために推奨します。また Vite は <b>UE4 の TAA</b> も改良しており、安定性、マテリアル（特に光沢のあるもの）の色再現、テクスチャの鮮明さが向上しています。
</p>
</tldr>

アンチエイリアシングは、Vite のレンダリングの考え方が最もよく表れる部分です。Epic の Unreal Engine 5 と異なり、Vite は既定でネイティブ解像度で描画し、高いフレームレートを目標とします。そのためアンチエイリアシングのソリューションは、完全なネイティブ 4K 出力の画質上の利点を保ちながら、時間的な安定性を優先しています。ネイティブ 4K はピクセル密度が高いため、低い内部解像度と比べてそもそもエイリアシングが少なくなります。同じ出力解像度で比較すると、内部解像度の違いから、Vite は UE5 に対して実質的にスーパーサンプリングを行っていることになります。

<note>
Epic の UE 5.8 は、既定で目標のピクセル数の 4 分の 1（各軸 50%）の内部解像度を使います。この挙動は複数のレンダリングパスに見られ、TSR を無効にしても、エンジンは TAAU や基本的な空間アップスケーリングなど、ネイティブではない別のスケーリング手法にフォールバックすることがあります。Vite にはそのような挙動はなく、常に画面の完全なネイティブ解像度が既定です。Vite と UE5 を比較する際は、両方のエンジンが同じネイティブの内部解像度で描画していることを必ず確認してください。`stat unit` で現在の解像度と性能特性を確認できます。
</note>

## 利用できる手法

**プロジェクト設定 > エンジン > レンダリング > Default Settings** の **Anti-Aliasing Method** で、次の手法を選べます。

| 手法 | 列挙値 | `r.DefaultFeature.AntiAliasing` | 備考 |
|---|---|---|---|
| None | `AAM_None` | 0 | エイリアシングあり。比較や AA のアーティファクトのデバッグに便利です。 |
| FXAA | `AAM_FXAA` | 1 | 安価なポストプロセスフィルター。エッジとともにテクスチャのディテールもぼかします。Vite の FXAA は標準より高品質で高速です（March Major）。 |
| TemporalAA | `AAM_TemporalAA` | 2 | UE4 の TAA より品質と安定性が向上。エイリアシングをよく解消しますが、鮮明さを犠牲にします。 |
| MSAA | `AAM_MSAA` | 3 | フォワードシェーディングのみ。サンプル数は `r.MSAACount` で指定します。 |
| **SMAA** | `AAM_SMAA` | **4** | Vite の推奨手法。空間的で履歴バッファを持たず、4 段階の品質を備えます。 |

## SMAA

Subpixel Morphological Anti-Aliasing は、画像を解析してエッジのパターンを見つけ、幾何学的にその両側をブレンドします。空間的な手法であり、1 つのフレームを見て、そのフレーム内でエイリアシングを解消します。

この性質こそが、SMAA が Vite に合う理由です。時間的な手法はフレームをまたいでサンプルを蓄積するため、動くオブジェクトの背後のゴースト、カメラを速く動かしたときのにじみ、そして TAA の出力が薄いワセリン越しに描かれたように見える全体的なソフトさが生じます。SMAA には履歴バッファがないため、そうした失敗は一切ありません。その代わりにサブピクセルのディテールの再構成はできず、描画されなかった情報を復元することはできませんが、そもそもネイティブ 4K で描画している場合には、それはそれほど重要ではありません。

Vite の SMAA は Unreal Engine の CMAA2 より 32% 高速と計測され、そのため CMAA2 は不要と判断されました。他のモルフォロジカルな手法も検討しましたが、Vite に実装する客観的な理由のあるものはありませんでした。実装は 2 つの世代を経ています。

| リリース | 実装 |
|---|---|
| [March Major](ueVite26-MarchMajor.md) から [July Major](ueVite26-JulyMajor.md) | Vite のコンピュート SMAA。SMAA の計算をインライン化した 3 つのコンピュートパスで、品質は `r.Vite.SMAA.Mode` で指定 |
| [August Major](ueVite26-AugustMajor.md) 以降 | Epic の UE 5.7 の SMAA パイプラインの移植。エッジ検出、エッジのピクセルだけにステンシルで限定したブレンドの重みの計算、近傍ブレンドの 3 段階で、4 段階の品質と選択可能なエッジ検出を備えます |

SMAA のリファレンスのアルゴリズム自体は上流から変更していません。Vite が独自の実装から引き継いだのは、SMAA のエリアテクスチャとサーチテクスチャの非同期読み込みで、これによりレンダースレッドからテクスチャアセットを読み込むことを避けています。

### SMAA を有効にする

```ini
; Config/DefaultEngine.ini
[/Script/Engine.RendererSettings]
r.DefaultFeature.AntiAliasing=4
```

ポストプロセスボリュームの **Anti-Aliasing Method** の上書きでカメラごとに指定するか、実行時に次のように設定します。

```
r.DefaultFeature.AntiAliasing 4
```

### 品質

| CVar | 既定値 | 値 |
|---|---|---|
| `r.SMAA.Quality` | `2` | `0` = Low、`1` = Medium、`2` = High、`3` = Ultra |
| `r.SMAA.EdgeMode` | `0` | `0` = 色によるエッジ検出、`1` = 輝度によるエッジ検出 |

`r.SMAA.Quality` には `ECVF_Scalability` が付いているため、スケーラビリティのグループから制御できます。既定は High で、[パフォーマンス目標](Performance-Targets.md) もこれを前提としています。Low と Medium は、エッジの品質の差をフレームタイムと引き換えにしてよい低いスケーラビリティの段階のためのものです。色によるエッジ検出は明るさの近い色どうしの境界も捉え、輝度による検出はわずかに安価で、ノイズの多いテクスチャで誤ったエッジを拾いにくくなります。

<note>
<p>
<a href="ueVite26-JulyMajor.md">July Major</a> までのリリースでは、代わりに <code>r.Vite.SMAA.Mode</code>
（<code>0</code> = Low、<code>1</code> = High）と <code>r.AntiAliasing.SMAA.Debug</code> を使います。August 以降に移行する際は設定ファイル内の名前を変更してください。古い名前は何も通知されずに無視されます。
</p>
</note>

### パイプライン上での SMAA の位置

Vite は SMAA を **トーンマッピングの前** に適用します。トーンマッピングの後に実行される FXAA とは異なります。これは意図的なもので、リニアな HDR 空間でエッジを解消することで、部分的に解消されたエッジのピクセルをトーンマッパーが増幅して、コントラストの高い境界で目に見える縁取りを生むことを避けられます。これはトーンマッピング後に SMAA を実装した場合によく寄せられる不満です。

実際の影響として、ブレンド位置が **After Tonemapping** のポストプロセスマテリアルは、すでにアンチエイリアシングされた画像を受け取り、SMAA は HDR 出力とも正しく組み合わさります。

### デバッグ

Shipping 以外のビルドでは次の CVar を使えます。

| CVar | 値 |
|---|---|
| `r.SMAA.DebugVisualization` | `0` = オフ、`1` = エッジテクスチャ、`2` = ブレンドの重み、`3` = 平滑化したエッジを強調したシーンカラー |

エッジの可視化は、SMAA が何もしていないように見える（通常は手法が実際には選ばれていない）場合や、ぼかしすぎている（通常は元の画像に高周波の成分が多すぎ、強いシャープニングやノイズのポストプロセスが原因であることが多い）場合を診断する最も早い方法です。

## アンチエイリアシングでは直らないエイリアシング

一部のエイリアシングはラスタライズによって生じたものではなく、コンテンツに作り込まれたもので、通常の AA 手法では解消できません。

- 滑らかなマテリアルに高周波の法線マップを使った場合の **スペキュラーエイリアシング**。AA ではなく、適切なミップの生成と法線からラフネスへの変換で直します。
- ミップの欠落や不適切な生成による **テクスチャのエイリアシング**。テクスチャのインポート設定で直します。
- フォリッジでの **アルファテストのちらつき**。ディザリングによる不透明度を検討するか、アルファテストを使う面積を減らします。

これらは `AAM_None` に切り替えて、エイリアシングがどこに現れるかを見ることで診断できます。シルエットのエッジではなくサーフェスと一緒に動くエイリアシングは、コンテンツの問題です。
