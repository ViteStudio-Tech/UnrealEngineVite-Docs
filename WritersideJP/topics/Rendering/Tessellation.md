# テッセレーションとディスプレイスメント

<tldr>
<p>
4.26 で非推奨になり Unreal Engine 5 で削除された、ワールドディスプレイスメントを伴うハードウェアテッセレーションは、Vite では引き続き機能します。マテリアルの <b>D3D11 Tessellation Mode</b> を設定し、<b>World Displacement</b> と <b>Tessellation Multiplier</b> のピンに入力します。レイトレーシングからは変位前のベースメッシュが見えます。
</p>
</tldr>

テッセレーションは GPU 上でジオメトリを細分化し、生成された頂点をディスプレイスメントマップに沿って移動させることで、ラスタライズのパスに本物のジオメトリのディテールを生み出します。シルエットが変わり、サーフェスは自己遮蔽し、変位した形のシャドウマップの影を落とします。例外はレイトレーシングのエフェクトです。[レイトレーシングとの関係](#interaction-with-ray-tracing) を参照してください。

## このページがある理由

Epic は 4.26 でハードウェアテッセレーションを非推奨にし、Unreal Engine 5.0 で削除しました。Nanite が解決するのは別の問題で、非常に密に作成されたメッシュを効率よく描画するものです。その後の UE5 のリリースでディスプレイスメント用の実験的な Nanite テッセレーションが加わりましたが、これは Nanite のメッシュと UE5 のレンダラーでしか動作せず、4.27 にはどちらもありません。

テッセレーションがないと成り立たないワークフロー:

- ハイトマップで駆動する **地形とランドスケープのディスプレイスメント**。ディテールはメッシュにベイクされたものではなく、手続き的で視点に依存します。
- 雪の堆積、足跡、変形、水面など、プレイ中に変位が変わる **実行時のディスプレイスメント**。
- タイリングするサーフェスでの **テクスチャ駆動のディテール**。1 つのマテリアルで、メッシュごとに高ポリゴンのジオメトリを作らずに、多数のメッシュのレンガ、石畳、樹皮に本物の奥行きを加えられます。
- ハイトマップのほうが同等の密なメッシュよりはるかに安価な、**メモリに制約のあるディテール**。

Vite は 4.27 のテッセレーションのパイプラインをそのまま維持しているため、これらのワークフローは引き続き機能します。

## マテリアルでテッセレーションを有効にする

設定はマテリアルの **Tessellation** カテゴリにあります。

<procedure title="ディスプレイスメント付きのマテリアルを設定する" id="setup-tessellation">
    <step>
        <b>D3D11 Tessellation Mode</b> を設定します。<b>Flat Tessellation</b> は元の面を滑らかにせずに細分化し、<b>PN Triangles</b> は細分化しながら元の面を滑らかにします。有機的な形状には通常 PN Triangles を、元のシルエットを正確に保つべき場合は Flat を使います。
    </step>
    <step>
        <b>Tessellation Multiplier</b> にスカラーを接続します。これはサーフェスの細分化の量を制御します。遠くのジオメトリが細分化されないよう、距離で制御してください。
    </step>
    <step>
        <b>World Displacement</b> にベクトルを接続します。一般的な形は、頂点の法線にハイトマップのサンプルとディスプレイスメントのスケールを掛けたものです。
    </step>
    <step>
        画面上の三角形のサイズに応じて細分化を調整するため、<b>Adaptive Tessellation</b> はオン（既定）のままにします。メッシュの UV の継ぎ目に亀裂が出る場合は <b>Crack Free Displacement</b> をオンにします。
    </step>
</procedure>

## 全体の制御

| CVar | 既定値 | 効果 |
|---|---|---|
| `r.TessellationAdaptivePixelsPerTriangle` | `48.0` | 適応的テッセレーションを使うマテリアルで目標とする、画面上の三角形の面積（ピクセル） |

値を下げると三角形が小さくなって細分化が増え、上げると細分化が減ります。全体のスケーラビリティの調整項目として便利です。スケーラビリティのグループから公開すれば、個々のマテリアルに触れずに、低い品質のプリセットでプロジェクト全体のテッセレーションを控えめにできます。

## コストと制御

テッセレーションは無料ではなく、失敗したときの影響が大きいものです。大きなサーフェスで倍率に上限がないと、数百万の三角形が生成されてフレームレートが崩壊することがあります。

**倍率は必ず距離で制限してください。** 標準的なパターンでは、テッセレーションの係数に距離による減衰を掛け、近くのサーフェスだけを細分化します。

- `Camera Position` と、オブジェクトまたはピクセルのワールド位置をサンプリングします。
- 距離を計算し、`Divide` と `Saturate` で 0〜1 の減衰に変換します。
- その減衰をテッセレーションの倍率に掛けます。

**三角形の密度を直接確認してください。** ワイヤーフレームのビューモードは暴走した細分化をすぐに明らかにし、`stat rhi` は描画された三角形の数を表示します。

**ディスプレイスメントの亀裂** は、UV の継ぎ目やメッシュの境界で、隣接する頂点が異なる量だけ変位する場所に現れます。マテリアルの **Crack Free Displacement**（既定ではオフ）をオンにするか、継ぎ目をまたいでハイトマップを連続させるか、境界でディスプレイスメントを 0 にマスクしてください。

**カリング。** バウンドは変位前のメッシュから計算されるため、バウンドの外まで大きく変位したジオメトリは、画面の端や影で消えることがあります。大きく変位させるメッシュでは、コンポーネントの **Bounds Scale** を上げてください。

## レイトレーシングとの関係 {id="interaction-with-ray-tracing"}

レイトレーシングにはテッセレーションが見えません。アクセラレーション構造はベースメッシュから構築されます。スタティックメッシュでは World Position Offset を評価できますが（コンポーネントのレイトレーシングの設定 **Evaluate World Position Offset** がオンの場合）、テッセレーションのステージを実行したり World Displacement を適用したりすることはありません。レイトレーシングの [反射](RT-Reflections.md)、[シャドウ](RT-Shadows-And-Ambient-Occlusion.md)、[DDGI](DDGI-Dynamic.md) のプローブのレイから見ると、テッセレーションしたレンガの壁も視差マッピングの壁と同じように平らです。

実際には次のようになります。

- **反射** には平らなベースの面が映ります。大きく変位したサーフェスを浅い角度から見ると、プライマリビューとの食い違いが目に見えます。
- **レイトレーシングのシャドウ** は平らな面から落ち、変位した面に当たります。そのため強いディスプレイスメントでは、両者が食い違う場所で自己シャドウの誤りや光漏れが出ることがあります。レイトレーシングのシャドウを受けるサーフェスではディスプレイスメントの振幅を控えめにするか、問題の出るライトの **Cast Ray Tracing Shadows** をオフにしてシャドウマップを使わせてください。シャドウマップにはディスプレイスメントが見えます。
- **DDGI** のプローブのレイはプローブの解像度で動作するため、違いが問題になることはまれです。
- 平らな代用品がないほうがましな場合は、コンポーネントの **Visible in Ray Tracing** のチェックを外して、レイトレーシングのエフェクトから完全に取り除いてください。

レイトレーシングのエフェクトに形を見せる必要がある場合は、形をメッシュに作り込むか、大きく滑らかな変形であれば、コンポーネントのレイトレーシングでの評価を有効にした World Position Offset を使ってください。

## 代替手段

本物のジオメトリが必要なときは、テッセレーションが適切なツールです。そうでない場合は次のとおりです。

| 手法 | それで十分な場合 |
|---|---|
| 法線マッピング | ライティングのディテールだけでよく、シルエットと自己遮蔽は重要でない |
| 視差オクルージョンマッピング | プライマリビューから説得力のある奥行きがあればよい。ジオメトリのコストはない |
| 作成済みの高ポリゴンメッシュ | 事前に分かっている静的なディテールで、メモリの予算が許す |
| **テッセレーション** | シルエットやシャドウマップの影が重要、またはディスプレイスメントが実行時に変わる。レイトレーシングからはベースメッシュが見える |
