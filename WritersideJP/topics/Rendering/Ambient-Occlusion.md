# アンビエントオクルージョン

<tldr>
<p>
選択肢は 3 つです。Vite の <b>最適化された SSAO</b>（既定で有効、最も低コスト）、<b>HBAO+</b>（より高品質、ポストプロセスボリュームで制御）、そして <b>RTAO</b>（レイトレーシング、最も正確で最も高価）です。これらは組み合わせられ、HBAO+ は SSAO のバッファの上に乗算されます。
</p>
</tldr>

アンビエントオクルージョンは、環境光が完全には届かないはずのくぼみ、接触点、囲まれた領域を暗くします。シーンに接地感を与える最も安価な方法の 1 つであると同時に、コストをかけすぎることが最もよくある場所の 1 つでもあります。

## Vite の最適化された SSAO

Vite は、標準の UE4.27 のスクリーンスペース AO のパスのメモリアクセスパターンを書き直しています。標準のパスと同じ結果をより低いコストで生成し、既定で有効です。

| 制御 | 既定値 | 備考 |
|---|---|---|
| `VITE_O_SSAO`（コンパイル時） | `1` | Shipping と Test のビルドはこの値に固定 |
| `r.Vite.SSAO`（実行時） | `VITE_O_SSAO` | Debug と Development のビルドのみ。`0` は標準の UE のパス、`1` は最適化されたパス |

実行時の CVar は、開発中に最適化されたパスと標準のパスを A/B 比較するためにあり、最適化の検証もこの方法で行いました。Shipping ではこの CVar は存在せず、パスはコンパイル時に組み込まれます。[コンパイル時スイッチ](Compile-Time-Switches.md) を参照してください。

標準の UE4.27 の SSAO の設定はすべて引き続き適用され、ポストプロセスボリュームの **Rendering Features > Ambient
Occlusion** にあります。Intensity、Radius、Quality、Power、Bias、Fade Out Distance などです。

[SSGI](SSGI.md) が有効で確実に実行される場合は、SSGI がアンビエントオクルージョンの項を提供し、SSAO は完全にスキップされます（[September Major](ueVite26-SeptemberMajor.md) 以降）。

## HBAO+

Horizon-Based Ambient Occlusion は NVIDIA のより高品質な AO の手法で、NvRTX のブランチから受け継いでいます。スクリーンスペースの球内ではなく水平線の方向に沿って深度バッファをサンプリングするため、くぼみでより正確な遮蔽が得られ、SSAO に特有のオブジェクトのシルエット周りのハローも少なくなります。

HBAO+ はスクリーンスペースの AO バッファを置き換えるのではなく、その上に **乗算** されるため、有効にすると両方が実行されます。

### 有効にする

| CVar | 既定値 | 効果 |
|---|---|---|
| `r.HBAO.Enable` | `0` | 全体の有効化 |
| `r.HBAO.HighPrecisionDepth` | `0` | `0` は内部深度が FP16、`1` は FP32。遠くのオブジェクトでの自己遮蔽のバンディングを避けるには FP32 を使用 |
| `r.HBAO.GBufferNormals` | `1` | `0` は深度から法線を再構成、`1` は GBuffer の法線を取得 |

<note>
CVar のヘルプテキストは HBAO+ を DX11 専用と説明しています。Vite は D3D11 と D3D12 の両方で実装しており（D3D12 のバックエンドは <a href="ueVite26-JuneMajor.md">June Major</a> で追加）、ヘルプの文字列は元の NVIDIA の統合から引き継いだまま更新されていません。
</note>

### ポストプロセスボリュームの設定

有効にした後は、ポストプロセスボリュームの **HBAO+** カテゴリで HBAO+ を調整します。これらはブループリントから読み書きできるため、実行時に制御できます。

| 設定 | 既定値 | 範囲 | 用途 |
|---|---|---|---|
| Power Exponent | `2.0` | 0〜4 | AO の結果に適用する暗さのカーブ。大きいほどコントラストが強くなります。 |
| Radius | `2.0` | 0.1〜2 | ワールド空間でのサンプリング半径（メートル） |
| Bias | `0.1` | 0〜0.2 | この角度より下のサンプルを除外します。平らな面の自己遮蔽を取り除くには値を上げます。 |
| SmallScale AO | `1.0` | 0〜1 | 細かなディテールの遮蔽の重み |
| Blur Radius | 2 ピクセル | 無効 / 2px / 4px | ノイズを減らすブラー |
| Blur Sharpness | `16.0` | 0〜32 | ブラー中のエッジの保持。大きいほどエッジを保ちます。 |
| Max Depth | `9500.0` | 0〜400 以上 | これより遠いビュー深度では HBAO+ を計算しません |
| Depth Sharpness | `50.0` | 0〜100 | 深度の不連続への感度 |
| Clamp Foreground AO | オフ | &mdash; | 近いジオメトリの AO を制限 |
| Foreground AO Distance | `100.0` | 0〜1000 | 手前のクランプに使う距離 |
| Clamp Background AO | オフ | &mdash; | 遠いジオメトリの AO を制限 |
| Background AO Distance | `1000.0` | 0〜10000 | 奥のクランプに使う距離 |

**Radius** は最も重要で、最も間違えやすい設定です。単位はメートルで、正しい値はシーンのスケールに完全に依存します。人間サイズのプロップがある屋内では小さな半径が、大きな屋外ではより大きな半径が適しています。大きすぎるとすべてに柔らかな灰色の膜がかかり、小さすぎると最も狭いくぼみにしか遮蔽が出ません。

**Max Depth** は分かりやすい性能の調整項目です。遠くのジオメトリは目に見える AO にほとんど寄与しないため、この値を下げると見た目の変化を最小限に抑えつつコストを減らせます。思い切った値に決める前に、シーンを通して確認してください。

## レイトレーシングアンビエントオクルージョン

RTAO の詳細は [RT シャドウとアンビエントオクルージョン](RT-Shadows-And-Ambient-Occlusion.md) で説明しています。簡単に言えば、実際に遮蔽のレイをトレースするため、画面外の遮蔽物も正しく扱え、見えているものしか知らないというスクリーンスペースの AO の根本的な制約がありません。

3 つの中で最も高価で、DXR が必要です。

## 選び方

| 目標 | 推奨構成 |
|---|---|
| スタイライズド 4K120 | Vite の SSAO のみ |
| パフォーマンス（ハイエンド）4K60 | Vite の SSAO。余裕があれば HBAO+ |
| フィデリティ（ハイエンド）4K30 | Vite の SSAO + HBAO+ |
| フィデリティ（フル RT）1440p30 | RTAO |

一般的なルールとして、AO はその結果を出せるもののうちフレームで最も安価なものにすべきです。[DDGI](DDGI-Dynamic.md) がすでにその空間の間接光を正しく解決しているなら、その上に重い AO をかけるのは二重に暗くすることになり、GI のソリューションが加えてもいない光を差し引くことになります。

<warning>
AO の重ねがけに注意してください。マテリアルの AO、SSAO、HBAO+、RTAO を同時に有効にすると、接触部が本来よりはるかに暗いシーンになります。各層が乗算されるためです。接触シャドウが物理的に妥当なのか単に暗いだけなのか分からない場合は、
<a href="Path-Tracing.md">パストレーシング</a> のリファレンスと比較してください。
</warning>
