# 静的 DDGI

<tldr>
<p>
ほぼ一瞬でベイクできるプローブボリュームです。従来のベイクライティングより高精度なバウンス、動くオブジェクトへのより良いカバレッジを備え、実行時のレイトレーシングのコストがかかりません。そのため、DXR に一切対応していない GPU でも動作します。
</p>
</tldr>

静的 DDGI は、[動的 DDGI](DDGI-Dynamic.md) と同じプローブボリューム、同じイラディアンスの計算、同じ八面体表現を使いますが、イラディアンスを実行時に継続的に求めるのではなく、ベイク時に一度だけ求めます。ローエンドの GPU や、レイトレーシングに対応していない GPU（GTX 900 / Radeon 5000 シリーズ以前）のためのパスです。

<note>
動的な RT DDGI は 2016 年の GTX 1060 6&nbsp;GB 以降で動作します。最低要件は、6&nbsp;GB 以上の VRAM を備えた
Pascal アーキテクチャの GPU です。
</note>

## 得られるもの

**ほぼ一瞬のベイク。** これが Lightmass との最大の違いです。プローブのイラディアンスのベイクは、ライトマップの UV とテクセルごとのラジオシティを解くより本質的に安価な問題であり、ベイクが数時間ではなく数秒で終わると、イテレーションの進め方そのものが変わります。

**従来のベイクライティングより高精度なバウンス。** プローブは実際のシーンのジオメトリをトレースして埋められ、平坦なライトマップの値ではなく方向を持つイラディアンスを保存します。そのため、ライティングをベイクした場所でもサーフェスは向きに応じて正しく反応します。

**動くオブジェクトへのより良いカバレッジ。** これがライトマップに対する構造的な利点です。ライトマップはライティングを
*サーフェス* に保存するため、動くオブジェクトは間接光のサンプルやボリュメトリックライトマップにフォールバックする必要があります。DDGI のプローブボリュームはライティングを *空間* に保存するため、キャラクター、ビークル、物理の破片など、ボリュームの中を動くものはすべて静的なジオメトリと同じ表現をサンプリングし、見た目も一貫します。

<note>
<b>実行時に DXR は不要です。</b> ベイク後はプローブのテクスチャデータがシリアライズされ、レイトレーシングのアクセラレーション構造は不要になります。これにより、静的 DDGI は極めてローエンドの GPU や、レイトレーシングに一切対応していないハードウェアでも使えます。
</note>

## 使うべき場面

| 状況 | 推奨 |
|---|---|
| 最低スペックが DXR に対応していない | 静的 DDGI |
| 最低スペックが非常にローエンドだが DXR には対応 | レイの予算を下げた動的 RT DDGI |
| ライティングが完全に静的（時間帯の変化なし、破壊可能なライトなし） | 静的 DDGI で十分 |
| ライティングが実行時に変わる | [動的 RT DDGI](DDGI-Dynamic.md) |
| 幅広いハードウェアで出荷する | ハードウェアの検出で両方を切り替え |

最後の行がよくあるケースで、動的なライティングを目標とするプロジェクトでも静的 DDGI を設定しておく価値がある理由です。2 つのモードはボリュームと作成作業を共有するため、両方に対応してもすべてのレベルのライティングを 2 回行う必要はなく、スケーラビリティの設定で済みます。

## セットアップ

<procedure title="静的 DDGI をベイクする" id="bake-static-ddgi">
    <step>
        動的モードとまったく同じように DDGI ボリュームを配置し、サイズを決めます。ボリュームの配置とプローブ密度の作成作業は共通です。
    </step>
    <step>
        ボリュームを静的モードに切り替えます。
    </step>
    <step>
        ライティングを確定させます。ベイク後に変わったものはプローブに反映されません。
    </step>
    <step>
        ベイクします。ベイクは十分に速いので、夜間のジョブではなくライティング作業の一部として気軽に繰り返してください。
    </step>
    <step>
        シーン内で動くオブジェクトを使って確認します。静的 DDGI がライトマップに最もはっきり勝るのはそこだからです。
    </step>
</procedure>

## 制限事項

静的 DDGI はベイクするものなので、それに伴う制限はすべて当てはまります。時間帯の変化はなく、移動したり明るさが変わったりするライトはバウンスに寄与せず、破壊されたジオメトリからのバウンスも反映されません。直接光は完全に動的なままにでき、固定されるのは間接光のバウンスだけです。

プローブの間隔が空間的な解像度を決めることに変わりはないため、接触ディテールについても同じ考え方が当てはまります。ここでも [SSGI](SSGI.md) の併用は有効で、SSGI はレイトレーシングを必要としないため、同じハードウェアで利用できます。

Vite はインポート時のライトマップ UV の生成を既定で無効にしている点に注意してください。[エンジンの既定値の変更](Engine-Defaults.md) を参照してください。静的 DDGI と併用して、または代わりに従来のライトマップを使う場合は、再び有効にする必要があります。

<note>
従来の Lightmass のライトマップは、静的 DDGI または動的 DDGI と組み合わせられます。両者はうまくブレンドされ、一般的にこの組み合わせでアーティファクトやライティングのつぶれは生じません。
</note>
