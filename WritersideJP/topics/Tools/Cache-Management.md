# キャッシュ管理

<tldr>
<p>
エンジンのルートにある <code>WipeShaderCache.bat</code> は、エンジンの Derived Data Cache、中間シェーダー、シェーダーのデバッグ情報を削除します。エディタの挙動がソースの変更と一致しなくなったときに使ってください。
</p>
</tldr>

Unreal は積極的にキャッシュします。それが反復作業を耐えられるものにしていますが、同時に、古いキャッシュによって正しい変更が効いていないように見えたり、間違った変更が効いているように見えたりすることもあります。

## スクリプトが消去するもの

`WipeShaderCache.bat` は、エンジンのルートを基準とした 3 つのディレクトリを削除します。

| ディレクトリ | 内容 |
|---|---|
| `Engine\DerivedDataCache` | コンパイル済みのシェーダー、クックしたテクスチャ、ビルドしたメッシュなど、あらゆる派生データ |
| `Engine\Intermediate\Shaders` | シェーダーのコンパイルの中間出力 |
| `Engine\Saved\ShaderDebugInfo` | シェーダーのデバッグシンボルと、プリプロセス済みのソースのダンプ |

各ディレクトリについて、削除した、見つからない、失敗した、のいずれかを報告します。失敗はほぼ必ず、まだ何かがファイルハンドルを保持していることを意味します。

<warning>
スクリプトを実行する前に、エディタとすべての <code>ShaderCompileWorker.exe</code> のプロセスを終了してください。シェーダーのコンパイルのワーカーはエディタより長く残ることがあります。削除に失敗した場合はタスクマネージャーを確認してください。
</warning>

消去した後、次にエディタを起動すると必要なものがすべて再コンパイルされます。大きなプロジェクトでは数十分以上かかることもあります。気軽に行わないでください。

## 消去すべきとき

<deflist>
<def title=".usf や .ush のファイルを変更したのに何も起きない">
シェーダーのソースの変更は通常反映されますが、エンジンレベルのグローバルシェーダーの変更は反映されないことがあります。まずコンソールで <code>recompileshaders global</code> か <code>recompileshaders changed</code> を試してください。完全な消去よりはるかに速く済みます。
</def>
<def title="コンパイル時スイッチを変更した">
<a href="Compile-Time-Switches.md">VITE_RT_PSO_DEBLOAT</a>、<code>VITE_O_SSAO</code> など、<code>VITE_*</code> のスイッチを変更すると、存在するシェーダーのパーミュテーションが変わります。C++ はエンジンの再ビルドで処理されますが、古い構成のキャッシュされたシェーダーが残ることがあります。切り替えた後は消去してください。
</def>
<def title="レンダラーに関わるエンジンの変更をプルした">
シェーダーのコードやシェーダーマップのキーを変更するマージによって、エンジンが誤って読み取るキャッシュが残ることがあります。
</def>
<def title="ソースと一致しないシェーダーのコンパイルエラーが出る">
古いキャッシュの典型的な症状です。報告されたエラーの行が、見ているファイルに存在しません。
</def>
<def title="エンジンの変更後に起動時にエディタがクラッシュする">
原因から除外するのが安上がりなので、詳しく調査する前に試す価値があります。
</def>
</deflist>

## 消去すべきでないとき

DDC の消去は重い手段で、それでは解決できない問題に使われることがよくあります。

- **プロジェクトレベルの問題。** このスクリプトが消去するのは *エンジン* の DDC です。プロジェクトには独自の
  `DerivedDataCache` フォルダーと、独自の `Intermediate` と `Saved` のディレクトリがあります。エンジンレベルの消去はそれらに触れません。
- **実行時の描画の不具合。** エフェクトが一貫して間違って描画されるなら、それはキャッシュではなくコードか設定の問題です。まず [コンパイル時スイッチの利用可否の表](Ray-Tracing.md) を確認してください。多くのレイトレーシングの機能は既定でコンパイル対象から外れており、そのコンソール変数は何も通知せずに何もしません。
- **シェーダーのコンパイル時間が長い。** 消去すると良くなるどころか悪化します。[シェーダーコンパイルと PSO](Shader-Compilation-And-PSO.md) を参照してください。

## より軽い代替手段

完全な消去の前に、次を試してください。

| 方法 | 消去するもの | コスト |
|---|---|---|
| `recompileshaders changed` | 変更したシェーダーのみ | 数秒 |
| `recompileshaders global` | グローバルシェーダー | 1 分未満 |
| `recompileshaders material <name>` | 1 つのマテリアル | 数秒 |
| プロジェクトの `Intermediate\` を削除 | プロジェクトのビルドの中間ファイル | プロジェクトの再ビルド |
| `Engine\Intermediate\Shaders` だけを削除 | DDC を残したまま、中間のシェーダー出力を消去 | 部分的な再コンパイル |

最後の方法は知っておく価値があります。再構築に高いコストがかかるのは DDC です。中間のシェーダーの状態だけを消去すればよい場合は、そのディレクトリを手で削除するほうが、スクリプト全体を実行するよりずっと安上がりです。

## キャッシュの場所

| キャッシュ | パス | スクリプトで消去されるか |
|---|---|---|
| エンジンの DDC | `Engine\DerivedDataCache` | はい |
| エンジンの中間シェーダー | `Engine\Intermediate\Shaders` | はい |
| シェーダーのデバッグ情報 | `Engine\Saved\ShaderDebugInfo` | はい |
| プロジェクトの DDC | `<Project>\DerivedDataCache` | いいえ |
| プロジェクトの中間ファイル | `<Project>\Intermediate` | いいえ |
| 共有／ネットワークの DDC | `BaseEngine.ini` の DDC の設定による | いいえ |
| ローカルユーザーの DDC | `%LOCALAPPDATA%\UnrealEngine\Common\DerivedDataCache` | いいえ |

<note>
チームで共有のネットワーク DDC を使っている場合、ローカルで消去してもたいてい意味がありません。ローカルのキャッシュは、消去のきっかけになった古いエントリも含めて、共有のものから再び埋められます。ローカルのキャッシュが問題だったと結論づける前に、共有の DDC の状態を確認してください。
</note>

## ディスク容量

エンジンの DDC は、開発中に際限なく大きくなります。多くのマテリアルやレイトレーシングのパーミュテーションを使うプロジェクトでは、数十 GB に達することもあります。再コンパイルのコストを受け入れたうえで、定期的に消去するのはディスク容量を取り戻す正当な方法です。

ディスク容量が本当の懸念であれば、より大きく恒久的な節約については [デブロートガイド](Debloat-Guide.md) を参照してください。
